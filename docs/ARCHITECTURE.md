# Architecture

Okie Motor is plain browser JavaScript with no build step beyond concatenation. Every file in `src/` is a classic
script that attaches to `window.OkieMotor` (and exports itself with `module.exports` under node, so the pure parts
are unit-tested without a browser). `tools/build.py` joins them into one file, `dist/okie-motor.js`, in the order of the
`<script>` tags in `harness/index.html`. One ordered bundle is deliberate: Home Assistant loads dashboard resources
in parallel, so separate files could not rely on load order.

```
src/              the modules (below)
tests/            node:test unit tests for the pure rules, plus the installer end-to-end test
harness/          index.html (loads src/), bundle.html (loads dist/), mock-hass.js, smoke.js, assets/
tools/            build.py, make-demo.py, serve.js, installer_template.py, gen-squircle.py
hemma/            edits.json: the exact-anchor edits the installer applies to Hemma
dist/             committed build outputs (okie-motor.js for HACS, okie-install.py, okie-demo.html)
docs/             this file, the measured FSC layout, install guides, screenshots
```

## Modules

Load order matters only for modules that read another module when they load (tiles needs icons, bento needs tiles and
feeds, island needs controls, and so on). New modules must be added to `harness/index.html`; the build refuses a
module that is missing from it.

| Module | What it does |
|---|---|
| `okie-core.js` | LRU cache, three-tier store (memory, localStorage, IndexedDB), event bus, EN/DE strings with fallback, settings with defaults, user overrides and a "changed" diff |
| `okie-squircle.js` | The four card shapes as CSS clip-paths (generated by `tools/gen-squircle.py`) |
| `okie-ui.js` | `h()` DOM helper, the icon set, glass design tokens, gestures, the 80 px fade-in scrollbar, error boundary |
| `okie-logic.js` | Pure rules: grouping, chip filters, quick-control actions, state wording, video lookup, FSC zoom and height-ladder maths, typewriter timeline, recency buckets, "does this read like a request" |
| `okie-search.js` | Fuzzy typo-tolerant matcher, intent parser (area + domain), ghost completion, usage learning with exponential decay, suggestions, exclusion patterns |
| `okie-overlay.js` | The one glass window for every popup (grows out of its button, focus trap, Escape), anchored morph popups, toasts, undo pill |
| `okie-controls.js` | Circular dial, linear slider, power button, segmented control, chips |
| `okie-domains.js` | Detail controls per domain (light, climate, cover, fan, lock, media, vacuum, camera, alarm, scene, sensor, weather and more) |
| `okie-icons.js` | Coloured device icons with on/off states and a few small loops |
| `okie-detail.js` | The detail panel: hero with video, five tabs (Controls, Context, History, Schedule, Settings), history charts |
| `okie-feeds.js` | Todos, calendar events, news feed sensors, tips, house-chronicle wording (pure rules plus fetchers) |
| `okie-chronicle.js` | "What the house did": turns the state stream into entries, folds flapping, persists the latest 200 |
| `okie-tiles.js` | Device cards, list rows, system tiles, the quick-control icon with its hold ring |
| `okie-bento.js` | Start screen: W1 favorites carousel, W2 gradient slider (weather, to-dos, news, calendar, tips), W3/W4 live tiles |
| `okie-notify.js` | Notifications from HA persistent notices and derived alerts (smoke, gas, water, tamper, batteries), the notification center, quiet hours, version watcher |
| `okie-rest.js` | Screensaver and deep-rest state machine, wake sources, display handoff, photo frame |
| `okie-appshell.js` | Shared frame for apps (hero with back button, icon tabs, scrolling body) |
| `okie-settings.js` | The Settings app: data-driven rows, sub-pages, search, "Changed" badge |
| `okie-apps.js` | Calendar and To-do apps, plus the app registry |
| `okie-energy.js` | Energy app (reads Home Assistant's Energy dashboard) |
| `okie-system.js` | Schedules, News, Assistant (HA Conversation), Tips, What's new; the shared assistant client |
| `okie-island.js` | Status island: values capsule, orb, capsule, notification list, live activities |
| `okie-zen.js` | Lock page: clock, greeting or quote, swipe/scroll/key to reveal |
| `okie-dock.js` | The left rail (bottom bar on small screens) with its configure-items rules |
| `okie-search-ui.js` | The persistent search panel: typewriter, chips, filter popup, results, AI chat |
| `okie-wallpaper.js` | View-wide wallpaper with an early apply (no flash) |
| `okie-splash.js` | Optional start-up splash |
| `okie-card.js` | `<okie-motor-card>`: the frame, zoom and height ladder, navigation, hass diffing, the `ctx` every module receives |

## The `ctx` object

`okie-card.js` builds one `ctx` and passes it to every view. It is the whole contract between modules.

| Member | Meaning |
|---|---|
| `hass()`, `state(id)`, `item(id)`, `formatState(st)` | Home Assistant state and the search engine's item for an entity |
| `lang()`, `t(key, vars)` | Current language and translation |
| `settings`, `store`, `engine`, `bus` | Settings (`get`, `set`, `reset`, `changed`, `on`), persistent store, search engine, event bus |
| `call(domain, service, data)`, `callWS(msg)` | Service calls and websocket messages (failures reject; nothing is applied optimistically) |
| `toast(type, msg)`, `sheet(opts)`, `defer(label, fn, onUndo)` | Toast, glass window (use `anchor: button` for a morph popup), six-second undo |
| `openDetail(id)`, `openApp(id)`, `openStart()`, `openBrowse(q)`, `back()` | Navigation |
| `favorites`, `usageScore(id)`, `suggestions(n)` | Favorites and the learning engine |
| `zoom()`, `panelHeight()`, `lock()`, `unlock()`, `isLocked()` | Frame state |
| `statusValues()`, `contextLine()`, `liveActivities()`, `haptic(ms)` | Island and lock-page data, vibration |

Bus events: `states` (changed entities), `nav`, `notes`, `rest`, `search`, `lock`, `resize`, `island-refresh`, `clear-cache`.

## Frame geometry

Measured from a live Fast Search Card (see `FSC-LAYOUT-SPEC.md`). The design column is 1200 px wide and scaled with
CSS `zoom = clamp(.65, .65 + ((width - 1080) / 520) * .35, 1)` for widths of 768 px and up. Rows: status island 72 + 12,
search row 94, 24 gap, bento grid. The panel height is `clamp(availableHeight / zoom - 137, 380, 672)` and the grid
is the panel height minus 96. When the grid gets short the layout steps down a ladder (`data-hoehe` on the stage):
`voll`, `kompakt`, `abwerfen` (small tiles dropped), `boden` (stacked). When the window is too narrow for the dock to
sit left of the column it becomes a bottom bar.

## Recipes

**A new setting.** Add a row to `ROWS` in `okie-settings.js` (or push one onto `OkieMotor.settingsRows` from your own
module): `id`, `tab`, `group`, `type` (`toggle`, `segment`, `slider`, `text`, `entity`, `multi`, `number`, `action`, `info`),
`path`, bilingual `label` and `desc`. Put it on a sub-page with `page: 'island'` (pages are in `PAGES`). Give the path a
default in `okie-card.js` `DEFAULTS`; a test fails if it has none.

**A dock item or app.** `OkieMotor.apps.register({ id, nameKey, name, icon, order, category, render(container, ctx) })`.
`render` may return `{ update, dispose }`. Add the id to `DEFAULT_ORDER` in `okie-dock.js` to show it by default.

**A device control.** Add a factory to `OkieMotor.domains.factories[domain]`; the detail view calls it with `(ctx, item, opts)`.

**A language string.** `core.registerStrings('en', {...})` and the same keys for `'de'`. `tests/i18n.test.js` fails when
the two languages differ.

**Why tests run in node.** Everything that decides something (what a search matches, what a tap does, how the
layout scales, which notifications show) is a pure function with a test. The DOM code is checked by
`harness/smoke.js` in a real browser.
